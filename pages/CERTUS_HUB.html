Executive Summary: CERTUS-HUB is the central nervous system of the CERTUS suite. Far more than a simple launcher, it is a Runtime Hypervisor designed to solve the complex concurrency challenges inherent in high-performance Python computing. It enforces a secure initialization protocol for the Numba/LLVM JIT compiler, manages thread allocation across CPU cores to prevent GUI freezes, and provides a unified UX framework shared across all scientific modules (STRAT, DESIGN, RE, INDEX, METAL SINGLE/BILAYER).

1. The Scientific Problem: The Integration Challenge

Running advanced scientific code (using JIT compilation and multiprocessing) within a desktop GUI environment presents critical stability risks:

  • The GIL & Threading Conflict: Standard threading libraries (TBB, OpenMP) often conflict with Python's Global Interpreter Lock or the PyQt event loop, causing silent crashes or deadlocks.
  • Process Isolation: Launching heavy Monte Carlo simulations in the main process freezes the user interface.
  • Inconsistent State: Without a centralized entry point, modules might load conflicting configurations or material databases.

CERTUS-HUB solves this by acting as a Singleton Initializer. It sanitizes the environment variables before any scientific library is imported.

Phase I: Environment Locking (Steps 1–3)

Critical Initialization Sequence:
1. Threading Policy: The workqueue threading layer is forced via os.environ before any Numba import. This bypasses TBB/OpenMP which cause deadlocks when forked from a PyQt6 application.
2. Resource Reservation: NUMBA_NUM_THREADS is capped at CPU_COUNT − 1. This reserves a dedicated physical core for the OS and GUI event loop.
3. Process Isolation: multiprocessing.set_start_method('spawn') ensures child processes get clean copies of the environment, preventing fork-related state corruption.

Phase II: Shared Library Initialization (Steps 4–6)

Step 4 — Material Database: Loads indices.xlsx (one Excel sheet per material). Each sheet's wavelength and refractive index columns are converted to contiguous Float64 arrays and stored in MaterialDatabase for Numba-compatible vectorized interpolation.

Step 5 — Logging: Initializes a thread-safe QueueHandler that centralizes log messages from all parallel child processes into a single stream.

Step 6 — Numba Warmup: A background QThread triggers JIT compilation of the 3 most critical kernels: calculate_RT_vectorized_real_HL, simulate_growth_kernel, and compute_dynamics_kernel. This eliminates the ~5 second compilation latency on the user's first operation.

Phase III: Central Command Dispatch (Steps 7–8)

The PyQt6 dashboard presents launch buttons for each module. When a module is selected:

  • The Hub verifies that the module file (.py or .exe) exists on disk.
  • It creates a managed execution context with splash screen and error monitoring.
  • It calls the target module's init_certus_app() entry point, passing the sanitized environment, material database reference, and theme configuration.

4. Numerical Precision Policy

Since version 2026.02, all modules operate exclusively in double precision (float64 / complex128). This eliminates an entire class of subtle numerical bugs (silent Numba recompilation, accumulated rounding in TMM chains of 50+ layers) while the performance impact is negligible on modern 64-bit CPUs with AVX2/FMA.

Data Type Precision Usage
np.float64 ~15 significant digits Wavelengths, thicknesses, noise matrices, cost functions
np.complex128 ~15 digits (real + imag) Refractive indices $\hat{n} = n - ik$, TMM matrices, Fresnel coefficients
Why not Float32? In a 50-layer multilayer TMM, each matrix multiplication accumulates rounding errors. With Float32 (~7 digits), the cumulative error after 50 multiplications can reach $\sim 10^{-3}$ in transmittance — comparable to the physical effect being optimized. Float64 keeps accumulated error below $10^{-10}$, well below any measurement noise.

7. Key Architecture Advantages

7.1 "Workqueue" Stability

By strictly enforcing the workqueue threading policy at the root level, CERTUS-HUB eliminates the most common cause of crashes in Python scientific GUIs (race conditions between the C++ Qt event loop and the Numba parallel threads).

7.2 Modularity & Maintainability

The Hub decouples the launch logic from the scientific logic. Updates to the styling, logging, or threading policies are applied in certus_ui and the Hub, automatically propagating to all modules without rewriting their code.

7.3 Exact Analytic Gradients

A defining feature of the CERTUS architecture is the abandonment of numerical approximations (finite differences) in favor of Exact Analytic Derivatives. The core engine explicitly calculates the Jacobian matrix for both the Transfer Matrix Method (TMM) and the complex Tauc-Lorentz-Urbach dispersion models:

$$ \frac{\partial \mathbf{M}_{total}}{\partial d_j} = \mathbf{M}_{after}[j] \cdot \frac{d\mathbf{M}_j}{d d_j} \cdot \mathbf{M}_{before}[j] $$

By computing $\frac{\partial \text{MSE}}{\partial p_i}$ analytically via Numba-accelerated kernels, the L-BFGS-B optimizer navigates the error landscape with machine precision ($\sim 10^{-12}$). This prevents the "stagnation" often seen in optical thin film synthesis when gradients vanish in noise.

7.4 Unified TMM Convention

All modules share the same Transfer Matrix Method convention from _certus_physics_impl.py:

  • Macleod Convention: $\hat{n} = n - ik$ (k > 0), factor +1j in off-diagonal matrix elements.
  • Pre-multiply Air→Substrate: New layers are pre-multiplied ($\mathbf{L} \cdot \mathbf{M}$), consistent with the deposition order.
  • Incoherent Backside: Dual-matrix approach — forward matrix for $T$, reverse matrix for $R_{back}$, combined via the exact incoherent formula $T_{total} = T_{fwd} \cdot T_{ext} / (1 - R_{back} \cdot R_{ext})$.

The CERTUS Suite features a fundamentally modernized UI engineered for high-speed scientific workflows. Global Keyboard Shortcuts

To maximize efficiency, the interface actively maps physical keystrokes to core pipeline triggers:

  • Ctrl + S : Save current configuration natively.
  • Ctrl + O : Load an existing configuration.
  • F5 or Ctrl + R : Instantly launch the primary optimization or fitting Step (Step 2).
  • Ctrl + Z : Undo last configuration change (5-level undo stack via deque, active in all modules via CertusBaseApp).
  • Esc : Quickly dismiss detached windows, live monitors, and auxiliary floating charts.

Theme Toggle & Live Footer

A CertusThemeToggle action (☀/🌙) switches between light and dark themes system-wide at runtime without restart. The window footer dynamically displays the __version__ string from certus_core.py, Python version, and Qt version.

Dynamic Processing Feedback

Heavy Background Tasks (like full DP Strategy extraction or Numba lazy-compilation hooks) are completely thread-isolated. The architecture enforces Dynamic Wait Cursors (Spinners) and rich button Tooltips to provide absolute real-time state awareness without locking the application's event loop.
