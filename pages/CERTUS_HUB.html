CERTUS-HUB

Runtime Environment Supervisor & Unified Entry Point

Implementation review: 2026-10-03

Executive Summary: CERTUS-HUB lists the suite's scientific modules and support tools, prepares the Numba environment, and launches each selected module in its own process. It passes a file dropped on a module card to that module's command line and reports process startup or exit errors.
Offline note: These HTML pages load MathJax and Mermaid from a CDN (jsDelivr). Without internet access, formulas and flowcharts may not render fully; body text and tables remain readable.

1. The Integration Problem

Scientific modules need a predictable numerical runtime and a responsive desktop launcher:

  • Thread policy: Numba must see its thread settings before compilation begins.
  • Process isolation: each module runs outside the hub's Qt event loop.
  • File handoff: the chosen input file must reach the selected module.

CERTUS-HUB calls configure_numba_env before imports that use Numba and dispatches modules through QProcess.

2. Suite Architecture

The catalogue in certus_hub_config.py describes scientific workflows and support tools. ApplicationCard and GroupedApplicationCard render those entries; the hub starts the selected script rather than importing its scientific solver into the hub window.

3. Startup and Module Dispatch

flowchart TD A(["Start CERTUS_HUB"]) B["configure_numba_env before Numba-using imports"] C["Build the Qt hub and module catalogue"] D{"Operator selects a module and optional file"} E["QProcess starts a separate Python script in source mode"] F["QProcess starts CERTUS_HUB.exe --run-module NAME in frozen mode"] G["Hub watches start, exit and error output"] A --> B --> C --> D D -->|Source| E --> G D -->|Frozen| F --> G

configure_numba_env sets a source-keyed temporary cache and thread environment before a Numba-using module is imported. In source mode it defaults to the omp layer and reserves CPU capacity; in frozen mode it selects workqueue. Existing environment settings and an already-initialized Numba runtime can affect the result, so the precise values are conditional.

launch_module creates a QProcess for the selected script, or re-enters the single frozen executable with --run-module. An optional dropped file is passed as a command line argument. The module initializes its own application and data; the hub does not transfer an in-memory material database or call the module's Qt entry point in its own process.

The shared init_certus_app starts a one-time JIT warmup after each module has finished its imports. The hub reports process errors and abnormal exits to help diagnose startup failures.

4. Numerical Scope

The hub configures the process environment and chooses modules; it does not perform optical calculations or impose one numeric dtype on every algorithm. Precision, substrate handling and uncertainty must be checked in each module's model and report.

5. Inputs and Outputs

The hub reads its catalogue, a user-selected or dropped file path, and display/export preferences. launch_module passes the selected file as a command-line argument to the child process. The child module reads its own measurements and material data and decides whether to write a report.

The hub displays launch status and the end of a failed module's error output. Its auto-export option is a preference consumed by modules that implement export; it does not guarantee an Excel or HTML report for every operation.

7. Operational Limits

Separate processes keep a module crash from being a computation inside the hub's Qt event loop, but do not make a numerical method or thread combination intrinsically safe. The hub's thread defaults vary between source and frozen mode and can be affected by an existing environment.

Scientific interpretation belongs to the selected module and its input data. The hub neither computes optical gradients nor validates the physical accuracy of a reported fit.

9. Help and Module Status

The hub groups launcher cards by workflow and support-tool role. The File menu offers both automatic file-to-module selection and an explicit “Open file with…” choice. F1 opens the hub's shortcuts help.

When a child process ends unexpectedly, the hub reports its exit and a tail of its error output. A module's scientific progress, logs and export status remain inside that module's own window.
