CERTUS-STRAT

Advanced Optical Monitoring & Error Compensation Logic

Scientific Revision Pro 2026.04.17 — Complete Algorithm Documentation

Abstract: CERTUS-STRAT evaluates optical monitoring strategies by simulating nominal depositions with realistic noise and cumulative error propagation. The objective is to identify strategies that remain within specification despite deposition variability.

0. Algorithmic Overview

The CERTUS-STRAT algorithm is a three-step pipeline that transforms a nominal thin-film design into a robust optical monitoring strategy.

Algorithm Step-by-Step Summary Steps 0–1: compute nominal transmittance via TMM and precompute the index arrays and cumulative matrices $M_{before}[j]$ in Complex128.
Nucleation (optional): pre-rank initial block candidates using a parallel Numba kernel, then expand the block size adaptively with a 40% degradation threshold.
Phase A (per layer): for each layer, compute dynamics $\Delta T(\lambda)$ at all candidate wavelengths, apply safety filters, validate the survivors using Monte Carlo simulations, and propagate the resulting thickness errors into the TMM matrix cache for the next layer.
Phase B (global): dynamic programming groups layers into monochromatic blocks across three cost modes (THICKNESS, THICKNESS², SYM). Elite candidate mutations refine the top solutions. Each strategy is tested at three noise levels. Optional multi-seed consensus rescoring reduces seed dependence. The strategy with the lowest worst-case RMSE P95 is selected.
Key Principle — Cumulative Error Propagation: Unlike simplified approaches that evaluate each layer independently, CERTUS physically adds the simulated thickness errors of all preceding layers into the TMM matrix before evaluating the current layer. If layer 3 was deposited 2 nm too thick, the monitoring signal for layer 4 is shifted accordingly, as in a real deposition chamber.

REVISION 2026-08-04 — ce principe etait vrai a moitie, il l’est maintenant en entier

La propagation decrite ci-dessus etait bien implementee, mais son effet etait integralement neutralise au moment de l’arret. Le niveau de declenchement etait recalcule sur l’empilement reel : la parabole d’inversion interpolant exactement ce meme point, la resolution donnait Δd = bruit / P′ et rien d’autre. A bruit nul, une couche ressortait nominale quelles que soient les erreurs accumulees avant elle. Aucune compensation ne pouvait apparaitre ni etre mesuree.

Correctif 1 — cible figee. Le niveau de declenchement est desormais calcule sur l’empilement NOMINAL, comme en salle ou il est fige avant le depot. L’inversion reste faite sur le reel. L’ecart Tnom(d) − Treel(d) reapparait au numerateur : c’est le terme de compensation.

Correctif 2 — POEM (Percent of Optical Extrema Monitoring), selon Arsac, these 2025, eq. 2.2, et Zideluns et al., Opt. Express 29, 33398 (2021) :

TPOEM = (Ttrigger − Tprev TP) / (Tlast TP − Tprev TP)

Le point d’arret n’est plus une valeur de transmission mais une fraction de l’amplitude entre les deux derniers points tournants, pre-calculee sur le nominal puis reportee sur les extrema reellement observes. Toute distorsion affine du signal — gain ou offset photometrique, erreur d’indice, erreur d’epaisseur amont — est absorbee par construction. La compensation est obtenue par changement de variable, non par un coefficient. Balayage a 64 points sur 3× l’epaisseur nominale, pour disposer des virtual next turning points quand la couche en contient moins de deux ; repli sur la cible absolue sous 4 % d’amplitude.

Deux coefficients supprimes. non_monotonic_factor (divisait l’erreur par 2 des qu’un extremum etait traverse) et wavelength_change_penalty (majorait le bruit de la premiere couche d’un bloc) etaient les formes reduites d’un mecanisme que le modele ne pouvait pas produire. Il est desormais structurel ; les appliquer en plus compterait deux fois le meme effet.

Historique du bloc — la valeur des paquets monochromatiques, enfin quantifiee

A longueur d’onde inchangee, le signal de monitoring est continu d’une couche a l’autre : les points tournants deja traverses restent des mesures valides, exploitables pour recaler la couche courante. Au changement de lambda on repart sur un signal neuf et tout l’historique est perdu. Le balayage POEM porte donc desormais sur toute la longueur du bloc — 16 points par couche d’historique, 64 pour la couche courante, retour en arriere borne a 4 couches.

Defaillance DURE — le depot qui ne se termine jamais

Si l’arret theorique tombe juste AVANT un point tournant, une erreur amont peut faire tourner le signal avant d’avoir atteint la valeur visee. La machine attend alors un niveau qui ne viendra jamais et le depot part en vrille. Ce n’est pas une perte de precision, c’est un plantage — un evenement discret, structurellement invisible a un critere de RMSE.

A l’inverse, s’arreter APRES un point tournant est sur : l’extremum est deja compte, le signal s’en eloigne de facon monotone, le niveau est fatalement atteint. C’est la justification physique de l’asymetrie de check_extrema_proximity — zone interdite 3× plus large avant un point tournant qu’apres.

Le noyau detecte desormais deux defaillances dures, penalite 1e6 : le niveau vise n’est pas encadre par le signal reel entre le debut de couche et le prochain extremum ; et le nombre d’extrema comptes diverge entre nominal et reel — auquel cas la machine ancre POEM sur les mauvais points tournants. Ce second cas impose de detecter les extrema sur le signal REEL, celui que la machine mesure, et non sur le nominal : detecter sur le nominal doterait le simulateur d’une connaissance que la machine n’a pas.

1. Physical Model (Transfer Matrix Method)

The engine uses the Macleod Transfer Matrix Method (TMM), JIT-compiled through Numba with vectorized and threaded execution.

1.1 Conventions

  • Complex refractive index: $\hat{n} = n - ik$ with $k > 0$ for absorption (Macleod standard convention).
  • Matrix factor: $+i$ (I_VAL = +1j) in off-diagonal elements.
  • Accumulation order: Pre-multiply Air→Substrate. The system matrix is built as $M = L_1 \cdot L_2 \cdot \ldots \cdot L_N$, where layer 1 is on the air side and layer $N$ is on the substrate side.
  • Precision: All internal computations use float64 / complex128 to avoid mixed-precision recompilation.
  • Index consistency: All index arrays remain complex128 throughout, including the Phase A extrema checks and the Phase B robustness batch.

1.2 Characteristic Matrix of a Single Layer

For layer $j$ with complex index $\hat{n}_j$ and physical thickness $d_j$ at normal incidence:

$$ \delta_j = \frac{2\pi \hat{n}_j d_j}{\lambda} $$ $$ L_j = \begin{pmatrix} \cos \delta_j & \dfrac{+i}{\hat{n}_j} \sin \delta_j \\[6pt] +i\,\hat{n}_j \sin \delta_j & \cos \delta_j \end{pmatrix} $$

1.3 System Matrix and Transmittance

The total system matrix for a stack of $N$ layers is built by pre-multiplication from Air to substrate:

$$ M = \prod_{j=1}^{N} L_j = L_1 \cdot L_2 \cdots L_N $$ $$ T = \frac{4\,\text{Re}(\hat{n}_{sub})}{|M_{00} + \hat{n}_{sub}\,M_{01} + M_{10} + \hat{n}_{sub}\,M_{11}|^2} $$

where $n_{inc} = 1$ (air).

1.4 Incoherent Backside Correction

The substrate back face reflects incoherently. CERTUS uses a dual-matrix approach in calculate_detailed_growth:

$$ T_{total} = \frac{T_{fwd} \cdot T_{ext}}{1 - R_{rev} \cdot R_{ext}} $$
  • $T_{fwd}$: Forward transmittance from the F matrix (Air→Sub, pre-multiply).
  • $R_{rev}$: Reverse reflectance from the R matrix (Sub→Air, post-multiply) — a separate matrix accumulation, required for absorbing multilayers where $R_{fwd} \neq R_{rev}$.
  • $R_{ext} = \left(\frac{n_s - 1}{n_s + 1}\right)^2$: Fresnel reflectance at the substrate/air interface.
  • $T_{ext} = 1 - R_{ext}$.
  • Validity check: validate_backside_real_indices warns once per run if $|k_{layer}|$ or $|k_{sub}|$ exceed thresholds (constants K_MAX_LAYER_BACKSIDE, K_MAX_SUBSTRATE_BACKSIDE), since the incoherent approximation degrades for absorbing materials.

1.5 Growth Dynamics Kernel

compute_dynamics_kernel evaluates $T(d)$ continuously as a layer grows from $d=0$ to $d=d_{nom}$ in 1 nm steps. The dynamics metric is the peak-to-peak range:

$$ \Delta T(\lambda) = \max_{d \in [0,\,d_{nom}]} T(d) - \min_{d \in [0,\,d_{nom}]} T(d) \quad \text{(T}_{max} - T_{min}\text{)} $$

A large $\Delta T$ means the monitoring signal changes significantly during deposition at this wavelength, providing a strong trigger signal for the cut-off controller. Candidates for which $T_{min}$ (minimum T over full layer growth) falls below the minimum transmission floor (default 10%, parameter min_transmission_floor) are strictly excluded. This strict floor is enforced both during Phase A candidate selection and in a post-check on the final best strategy.

2. Optical Monitoring Simulation

2.1 Noise Model — Gaussian (Production Mode)

generate_noise_array generates gaussian noise for all Monte Carlo simulations. This is the production mode in STRAT.

$$ \epsilon \sim \mathcal{N}(0,\; \sigma^2/9), \quad \epsilon \text{ clipped to } [-\sigma, +\sigma] $$
  • $\sigma$ = trigger_tolerance / 100: The noise scale is derived from the spectrophotometer trigger tolerance parameter.
  • Gaussian: clipped to ±3σ (i.e., $\sigma_{raw} = \frac{1}{3}$) for numerical stability — this matches the 99.7% envelope of realistic sensor noise.
  • Deterministic pipeline: Phase A uses a globally pre-allocated noise matrix global_noise_matrix[runs × layers] generated once from phase_a_seed. Each layer gets a fixed column, ensuring reproducibility regardless of thread ordering.
  • Phase B uses COMMON RANDOM NUMBERS. The noise matrix depends only on (robustness_seed, noise_idx, num_runs, num_layers) and is served from a cache (_get_cached_sobol_noise, certus_strat_robustness.py:482-510) — it does not depend on the strategy. The _strat_idx argument of _test_strategy_robustness_task is underscore-prefixed and deliberately unused (:524).
    This is the right design and it matters: every strategy faces the same noise realisations, so the comparison between two strategies is paired and the noise largely cancels in the difference — which is the only thing a ranking depends on.
    ⚠️ A previous version of this page claimed seed = robustness_seed + strategy_idx × 10⁵ + noise_idx. That was wrong: it would have given each strategy an independent draw and made the ranking far noisier.
    The Sobol seed itself is scrambled — base_seed × 2 654 435 761 + noise_idx × 40 503 (:509) — because the naive base_seed + noise_idx made distinct pairs collide: (seed 42, level 1) and (seed 43, level 0) both gave 43, hence the same noise.
  • The legacy distribution argument is accepted for backward compatibility but intentionally ignored — behavior is always gaussian.

2.2 Non-Monotonic Error Model

Beyond pure trigger noise, the simulation optionally adds a systematic offset via compute_probe_offset_nm_from_ratio. The effective measured thickness incorporates:

Growth error components: 1. Gaussian trigger noise $\epsilon \cdot d_{nom}$: spectrophotometer trigger uncertainty.
2. Probe offset $\delta_{probe}$ (nm): systematic bias from non-monotonic growth (thermal drift, chamber vibrations). Controlled by non_monotonic_error_factor.
3. Two modes (non_monotonic_mode): NON_MONOTONIC_MODE_ATTENUATE (default) vs NON_MONOTONIC_MODE_REJECT.

2.3 Cumulative Error Propagation

The key innovation of CERTUS is that thickness errors are physically propagated through the TMM. If layer $i$ was deposited with an error $\delta d_i$:

Error Propagation Mechanism:
$$ \delta d_i^{(r)} = d_{nom,i} \cdot \epsilon^{(r)} + \delta_{probe} $$
1. Layer $i$ is deposited with actual thickness $d_i + \delta d_i^{(r)}$ in run $r$.
2. The TMM matrix is updated with this real thickness.
3. The monitoring signal for layer $i+1$ is computed from this perturbed matrix.
4. The cut-off for layer $i+1$ is triggered based on the perturbed signal — which may itself introduce an additional error $\delta d_{i+1}$.
5. This cascade continues for all $N$ layers.

This is implemented in simulate_stack_robustness_batch which processes $N_{runs}$ independent realisations in parallel using Numba prange.

2.4 Reality-Feedback Loop in Phase A

Before evaluating layer $i$, the TMM matrix cache is rebuilt from the average simulated thicknesses of layers $0 \ldots i{-}1$. A temporary per-layer cache (layer_matrix_cache) is computed via precompute_matrix_cache_kernel using only the scan wavelength grid. This means the dynamics $\Delta T$ seen at layer $i$ are already shifted by the reality of previous depositions — a key differentiator from static optimisation approaches.

3. Phase A: Layer-by-Layer Candidate Search

Orchestrated by optimize_block_strategy_hybrid, Phase A evaluates every layer independently (but with cumulative error feedback) to find the best monitoring wavelengths.

3.1 Step A.1 — Dynamics Ranking

calculate_dynamics_ULTIMATE computes the peak-to-peak $\Delta T(\lambda_k) = T_{max} - T_{min}$ for every candidate $\lambda_k$ in the scan range. Candidates are sorted by $\Delta T$ descending. The function also returns $T_{init}$, $T_{final}$, and $T_{min}$ per candidate for downstream filters.

3.2 Step A.2 — Safety Filters

  • Dynamics threshold: Reject candidates with $|\Delta T| < \text{dynamics\_threshold}$ (default 2.5%, configurable).
  • Strict T_min floor: Reject any $\lambda$ for which $T_{min}$ drops below min_transmission_floor (default 10%) at any point during layer growth. This is a strict rule: candidates that pass the dynamics test but fail the floor are categorically excluded.
  • Extrema exclusion: check_extrema_proximity_batch rejects wavelengths near T(λ) maxima/minima. The asymmetric start check is activated when the monitoring wavelength changes vs. the previous layer (prev_layer_wl awareness), giving a wider start margin during monochromator repositioning.
  • Spectral resolution: Resolution curvature check: the nominal stack must resolve $\Delta\lambda \geq 1$ nm at the candidate — computed from the T(λ) curvature (tolerance tied to trigger_tolerance).
  • λ₀ fallback: The reference wavelength is always included as a candidate, unless it fails the strict T_min floor.
  • Scan limit: Top phase_a_scan_limit (default 300) dynamics-passing candidates are forwarded to extrema/resolution checks.
Survival log is emitted per layer: [SURVIVAL L{i}] Dyn-OK / Tfloor-OK / Safe-Extrema / Resolution-OK counts for full pipeline traceability.

3.3 Step A.3 — Monte Carlo Validation

For each surviving candidate $\lambda_k$:

Vectorized Monte Carlo (Numba validate_wavelengths_batch): 1. Use column $i$ from the pre-allocated global_noise_matrix (gaussian, seeded by phase_a_seed).
2. For each run $r$, simulate the full growth of layer $i$ at wavelength $\lambda_k$ using cumulative history from runs_history_matrix. A candidate that reuses the previous layer's wavelength extends the current block and inherits its turning-point history (block_start_arr) — without this, Phase A is blind to the block value that Phase B models.
3. Compute thickness error: $\Delta d_r = |d_{simulated}^{(r)} - d_{nominal}|$, over the runs that terminate.
4. Return four columns per candidate, not one.

validate_wavelengths_batch returns a $(n_{cands}, 4)$ array: $Q_{0.95}(\Delta d_r)$, its standard deviation, the crash rate, and the compensation gain. The P95 and the standard deviation are computed only on runs that terminate: leaving the $10^6$ sentinel in would mix nanometres with a failure counter.

Cost — two terms, both in nanometres, no fitting constant: $$ \text{Cost}(\lambda_k) = Q_{0.95}\left(\Delta d_r\right) \;+\; w \cdot g(\lambda_k) \cdot \varepsilon_{\text{prev}} $$ $g(\lambda_k)$ is the compensation gain — how much of an upstream error the layer carries forward ($g < 1$ self-compensates, $g > 1$ amplifies). It costs two noise-free evaluations, no Monte Carlo. $\varepsilon_{\text{prev}}$ (phase_a_prev_error_nm) is the P95 measured on the Monte Carlo states actually propagated — measured, not postulated. $w$ is phase_a_compensation_weight, default $1$.

Below 0.05 nm — less than one atom — $\varepsilon_{\text{prev}}$ is floored to zero and the second term vanishes.

The crash rate is NOT part of the cost.

A strategy whose deposition does not terminate is not mediocre, it is unusable. It is eliminated, as in Phase B — a candidate is dropped when $\text{crash} \geq 1 - (1-0.05)^{1/N}$ or when $g < 0$ (gain not measurable: the layer does not terminate even at zero noise).

🔴 The per-layer threshold is DERIVED from the per-strategy one, it is not copied into it. The crash rate compounds over the height of the stack: a layer safe at 99.9 % still loses $1-(1-0.001)^{48} = 4.7\,\%$ of depositions over 48 layers. Reusing Phase B's 5 % as-is would make the filter inoperative — 5 % per layer allows 91 % failure over 48 layers. For $N = 48$ the threshold is 0.107 %, forty-seven times stricter.

3.4 Step A.4 — Error Propagation + Normalization

The best wavelength is selected for this layer. update_run_states_kernel saves the simulated thickness for each of the $N_{runs}$ realisations, so that the next layer's TMM matrix already includes the accumulated error history. After all layers complete, Phase A costs are normalized by the mean cost and squared to produce raw_results_sq for balanced DP input in Phase B.

3.5 Layer 1 Attenuation (optional)

When Smart Nucleation is inactive, the cost of Layer 1 can be attenuated by layer1_cost_attenuation_factor (default 1.0, i.e. no attenuation). Values $< 1.0$ reduce the penalty for the first layer, useful when the initial deposition statistics are less reliable.

3. Stratégies « prometteuses » ⚠️ Le mot qui coince est prometteuses. Choisies par un coût dont ρ = −0,04 : l'ensemble testé n'est pas prometteur, il est arbitraire.
4. La « meilleure » ⚠️ Sans définition dans le code : classement contre le spectre nominal, non pondéré, et STRAT n'a jamais reçu la cible.

Une seule grandeur, pas deux. « Ce que je veux, c'est la meilleure stratégie » + « si 95 % des dépôts fonctionnent, c'est gagné » + « le plus important est la cible spectrale respectée » définissent $P(\text{le filtre sorti est conforme à la cible})$.
Un dépôt qui plante ne produit pas de filtre conforme ; un dépôt hors spec non plus. Les deux sont le même échec — il n'y a donc pas deux critères à arbitrer, et pas de front de Pareto à rendre. On affiche les deux causes séparément, parce qu'un run perdu et un filtre hors spec n'ont pas le même sens économique, mais on optimise leur somme.

Conséquence sur la recherche : puisque le tri est fait par la statistique, la DP n'a plus à bien classer — elle doit bien couvrir. C'est un cahier des charges bien plus facile que celui auquel elle échoue aujourd'hui.

🔴 ÉTAPE 3 — « prometteuses » : le nœud du problème

48 couches donnent 247 ≈ 1,4·1014 découpages en blocs contigus, multipliés par les affectations de λ. L'énumération est exclue : il faut un générateur, et il doit valoir mieux que le hasard.

L'observation qui débloque : $P(\text{conforme})$ se factorise en deux morceaux de nature opposée. $$P(\text{conforme}) = \underbrace{P(\text{le dépôt se termine})}_{\text{SÉPARABLE}} \times \underbrace{P(\text{spectre dans la spec} \mid \text{terminé})}_{\text{NON SÉPARABLE}}$$ Le rendement est séparable : un dépôt se termine si chaque couche se termine, $\prod(1-p_i)$, dont le logarithme est additif — exactement ce qu'une DP de Bellman optimise exactement. La précision ne l'est pas : les erreurs se composent et se compensent, seul le Monte-Carlo en juge.

La DP doit optimiser la partie séparable et laisser l'autre au Monte-Carlo. Aujourd'hui elle fait l'inverse — elle optimise un proxy de précision (ρ = −0,04) et traite le rendement comme un couperet binaire.

🔴 Et la donnée existe déjà, jetée à la dernière ligne. La Phase A calcule le taux de plantage par couche et par longueur d'onde (results_fast[idx, 2], rangé en certus_strat_service.py:1081) et ne s'en sert que comme seuil binaire : if crash_rate >= crash_tol: eliminated.append(entry). Une λ à 0,001 % et une à 0,106 % sont traitées à l'identique, alors qu'elles diffèrent d'un facteur cent sur la seule grandeur qui compose sur la hauteur de l'empilement.
raw_results_thickness conserve les entrées complètes (objectives.py:313), mais la carte donnée à la DP ne garde que x["cost"] (pipeline.py:103).
Correctif : une carte parallèle crash_map[couche][λ] et l'objectif $\min \sum_\ell -\log\left(1 - p(\ell,\lambda)\right)$ — le log du rendement, exactement. Ce n'est plus un proxy : c'est une composante directe de $P(\text{conforme})$, à coût nul.
⚠️ L'indépendance entre couches est approximative — celles d'un même bloc partagent l'historique de points tournants. À mesurer, pas à supposer.

🔴 Mais le vrai levier manque totalement : la recherche locale. Puisque le Monte-Carlo est le juge et que le budget n'est pas contraint, le meilleur générateur n'est pas un générateur. Partir des survivantes et perturber — déplacer une frontière de bloc, changer la λ d'un bloc, fusionner, scinder — en réévaluant chaque perturbation au Monte-Carlo sur $P(\text{conforme})$. Pas de proxy, pas de séparabilité, pas de problème de corrélation.
ELITE s'en approche et échoue deux fois : il perturbe à ±1 nm, soit sous le pas de grille donc sans signification physique, et il juge sur le mauvais critère. Il produit les 551, 552, 553, 554 observés en tête de classement.

« Prometteuses » recouvrait trois choses distinctes qu'on confondait en un seul coût : le rendement se prédit, la diversité se construit, la précision ne se prédit pas — elle se mesure, puis on grimpe dessus.

4. Phase B: Block Grouping & Robustness Screening

4.1 Dynamic Programming Segmentation

Minimizing monochromator movements is crucial for process speed and reproducibility. CERTUS groups layers into monochromatic blocks (contiguous layers monitored at the same wavelength) using Sequential Dynamic Programming via _dp_kernel / _compute_valid_blocks_kernel (Numba kernels imported from _certus_physics_impl).

$$ V_k(i) = \min_{0 \le j < i} \left\{ V_{k-1}(j) + \min_{\lambda \in \Lambda} \sum_{m=j+1}^{i} \text{Cost}(m, \lambda) \right\} $$

Bellman state equation:

  • $V_k(i)$: cumulative minimum cost (corresponding to DP[k][i]) for covering layers $1 \dots i$ with exactly $k$ blocks.
  • $j$: optimal cut point (end of block $k-1$).
  • $\text{Cost}(m, \lambda)$: cost of layer $m$ monitored at $\lambda$, as defined in §3.3 — $Q_{0.95}(\Delta d) + w \cdot g \cdot \varepsilon_{\text{prev}}$, not the P95 alone. Candidates eliminated on crash rate never reach the DP.
  • The inner minimization loop corresponds to $\text{BlockCost}(j, i)$.

Ce que cette DP peut voir — et ce qu'elle ne peut pas

1. Le coût d'un bloc est la SOMME BRUTE des coûts de ses couches (certus_strat_dp.py:61), et la DP additionne les blocs (:118). L'objectif minimisé est donc exactement $\sum_{\ell} \text{Cost}(\ell, \lambda_{\text{bloc}(\ell)})$.
Conséquence structurelle : fusionner deux blocs adjacents à la même λ ne change rien au coût. La DP est aveugle au découpage — seule la contrainte $k = n_{\text{blocks}}$ le fixe. Or la valeur physique d'un bloc est précisément que le signal reste continu à λ constante et que l'auto-compensation opère. Cette valeur ne figure pas dans l'objectif. C'est ce que les bonus de symétrie et les passes ELITE tentent de rattraper après coup.

2. n_blocks est un compte de coupures, pas de blocs monochromatiques. Deux blocs adjacents à la même λ sont comptés comme deux alors qu'en salle c'est un seul — le signal n'est pas interrompu. Le nombre affiché ne veut donc pas dire ce qu'il semble dire.

3. Seules les 10 meilleures λ par bloc entrent dans la DP (certus_strat_dp.py:117, min(10, bl_count), en dur). Mesuré sur l'exemple (scripts/probe_block_wls.py) : le cap mord sur 38 blocs sur 40, jetant 8 candidats en médiane sur 18 disponibles. Mais ce qu'il jette est la queue — le 10e retenu coûte déjà ×2,2 le premier en médiane — et les 10 retenus s'étalent sur 95 nm en médiane, couvrant 4 régions distinctes alors que coût(λ) n'a que 2 à 5 minima locaux. La structure est donc déjà capturée. Le vrai élagueur n'est pas ce cap, c'est la Phase A, qui réduit ~51 λ scannées à 1–27 survivantes par couche.

4. Un bloc n'est valide que si TOUTES ses couches ont cette λ parmi leurs survivantes de Phase A (:64-66). Une élimination sur une seule couche tue le bloc entier. L'énumération part de la couche la plus contrainte (:36-45) — heuristique de propagation de contraintes, et c'est un bon choix.

5. La DP conserve top_k×2 chemins par état (:93). C'est bien une recherche des k meilleurs chemins, pas un simple faisceau : l'optimalité de Bellman est préservée pour l'objectif donné. Le problème n'est pas l'algorithme, c'est l'objectif.

The algorithm explores block counts from a contractual range controlled by the iter_divider_start and iter_divider_end parameters, together with the fixed counts {1, 2, N}. In Fast Auto mode (fast_auto_blocks=True), four preset divider pairs are combined to broaden the coverage.

Fast Auto block presets (divider_start / divider_end): Compact (20/12), Balanced (12/6), Extended (8/4), and Very Extended (6/2.5). Each preset is computed via _compute_blocks_range_contractual and the results are combined, typically yielding 5–15 distinct block counts per run.

mine_strategies_for_block_count runs three DP passes in parallel (ThreadPoolExecutor) for each block count:

  • THICKNESS: raw P95 RMSE costs.
  • THICKNESS²: normalized squared costs for balanced block weighting.
  • SYM: symmetry-adjusted costs (see §4.3).

Up to five top-k strategies per block count and per pass are collected and validated against the _validate_strategy_blocks_contract schema (contiguous coverage, correct n_blocks, valid wavelengths).

4.2 Elite Candidate Generation

_generate_elite_candidate_strategies creates local-neighborhood variants around the top-ranked initial strategies before the final robustness evaluation:
  • Wavelength mutations: each block's monitoring wavelength is shifted by one neighboring step in the scan grid.
  • Boundary shifts: block boundaries are moved by one layer between adjacent blocks while preserving total layer coverage.
All elite candidates are validated against the block contract before being added, and duplicates are rejected through block-signature hashing. This step generates up to 120 additional strategies per run.

4.4 Full Monte Carlo Robustness Screening

run_final_simulation_block evaluates each candidate strategy under realistic conditions.

Robustness screening (_test_strategy_robustness_task): 1. For each noise level $\sigma \in \{0.5\sigma_0,\; \sigma_0,\; 2\sigma_0\}$ (configurable via robustness_noise_factors):
 a. generate a bounded Gaussian noise matrix of size $N_{runs} \times N_{layers}$.
 b. apply a wavelength-change penalty when $\lambda$ switches between adjacent blocks.
 c. run simulate_stack_robustness_batch to propagate cumulative errors through the stack.
 d. compute the spectral RMSE versus the nominal T(λ) via compute_batch_rmse.
2. Rank strategies by the worst-case CVaR95 across the tested noise levels (was the P95 — see below).
3. Select parallel or sequential execution automatically via get_safe_worker_count().
4. Filter non-finite robustness scores before final ranking.

🔴 Le RMSE est mesuré contre le NOMINAL, pas contre la cible

L'étape 1.d compare à T_nom, la transmission des épaisseurs nominales (certus_strat_robustness.py:211), et c'est ce tableau qui part en argument T_target de compute_batch_rmse (:706-712). Le RMSE est non pondéré, à pas constant, sur toute la plage.

Et STRAT n'a jamais reçu la cible : zéro occurrence de targets dans tout le module, alors que DESIGN la porte sous forme de zones {lmin, lmax, tmin, tmax, w}. STRAT répond donc à « quelle stratégie reproduit le mieux le spectre des épaisseurs conçues ? », et non « laquelle respecte le mieux la cible ? ».

Sur le dichroïque de l'exemple, plage 400–700 nm au pas de 1 nm : la bande bloquée pèse 146 points sur 301 et son exigence est < 0,1 % — un demi-point d'écart y vaut cinq fois hors spec — mais elle compte exactement autant que la bande passante, où le même écart est invisible.

⚠️ Distinction à ne pas rater. Le point visé pendant le dépôt doit rester le nominal figé : c'est le mécanisme même de l'auto-compensation. Seule la figure de mérite qui classe les stratégies doit passer à la cible pondérée.

2026-08-05 — CVaR95 remplace le P95 comme fonctionnelle de classement

Un quantile est la fonctionnelle la moins efficace d'un échantillon : il est déterminé par la seule queue haute. Nombre de points qui décident réellement d'un P95 :

N tirages points décidant le P95 résolution sur crash_rate
6 — mode fast un seul (le maximum) 17 % pour un seuil à 5 %
25 un à deux 4 %

La CVaR95 — moyenne des 5 % pires, expected shortfall — garde exactement la même sémantique de risque mais moyenne la queue au lieu d'en piocher un point. À N égal, la variance de l'estimateur est nettement plus basse, sans un seul tirage supplémentaire.

4.5 Consensus Multi-Seed Ranking (optional)

When enable_consensus_ranking=True, the top-k strategies (consensus_top_k, default 12) are re-evaluated across multiple seeds (consensus_seeds) to reduce seed-dependent outliers:
  • mean: simple average across seeds.
  • worst: worst-case seed score.
  • mean_std (default): $\text{score} = \mu + w \cdot \sigma$, with consensus_std_weight (default 0.35).
A cache keyed on strategy signature, seed, num_runs, and noise signature avoids redundant re-evaluations within a session. Consensus is applied both before and after elite expansion.

4.6 Post-Check: T_min Floor on Best Strategy

After ranking, the best strategy undergoes a final validation via _validate_strategy_min_transmission_floor. For every layer, the dynamics are recomputed at the assigned monitoring wavelength and $T_{min}$ is checked against min_transmission_floor. Any violation raises a RuntimeError to prevent acceptance of an invalid strategy.

5. Smart Nucleation (Optional)

For stacks with many layers, the first few layers are critical because errors propagate cumulatively. find_robust_nucleation_wavelength_adaptive identifies a nucleation wavelength and block size that stabilize the initial layers:

Adaptive nucleation algorithm: Phase 1: fast pre-ranking of candidate wavelengths using rank_nucleation_candidates_kernel (parallel Numba). Keeps the top 10.

Phase 2: for each top candidate, test growing block sizes (2, 3, 4…) and run find_nucleation_adaptive_kernel with full noise simulation.
 • If RMSE per layer degrades by more than 40% when adding a layer, stop growing.
 • If RMSE exceeds 1.5 nm/layer, reject the candidate.

Scoring: $\text{score} = \text{block\_size} \times (1 - \text{RMSE})$.

Integration in Phase B: the nucleation wavelength and size are passed to mine_strategies_for_block_count via apply_nucleation_constraint, which locks the DP cost map for layers 0…nucleation_size to use only the nucleation wavelength.

  • sp_buffer: batched SP emission (flushes every 500 spectra) to reduce queue pressure.
  • indices_cache: per-context wavelength-keyed index cache.
Contexts are activated via with ctx.activate(): for clean scoping. Workers initialize their own sub-context via StratContext.set_current(ctx). The global APP_CONTEXT dictionary is maintained for legacy compatibility during the migration.

6.2 RobustMaterialDatabase

RobustMaterialDatabase (in certus_strat_db.py) wraps the standard MaterialDatabase with a three-tier fallback strategy for index retrieval:
  1. Context-injected database (StratContext).
  2. Global APP_CONTEXT database.
  3. Numeric fallback constants (H: 2.1, L: 1.46, Sub: 1.52). The fallback does not use n = 1.0 because that would produce an incorrect T = 1.0 for a bare substrate.

6.3 Smart Index Retrieval

smart_get_refractive_index and smart_get_refractive_indices_vectorized shadow the physics module counterparts and implement the same four-tier fallback: explicit database argument → StratContext database → APP_CONTEXT database → physics fallback. These are aliased as the module-level get_refractive_index and get_refractive_indices_vectorized, so all internal code uses the same retrieval path.

7. Post-Optimization Analysis

7.1 Spectral Resolution Check

_calculate_strategy_spectral_resolution sweeps every (layer, monitoring wavelength) pair and computes the curvature-based resolution limit: $$\text{res\_limit} = \Delta\lambda \cdot \sqrt{T_{tol} / \kappa}$$ where $\kappa$ is the curvature of T(λ) at the monitoring wavelength and $T_{tol}$ is the trigger tolerance. The worst layer is reported in the output.

7.2 Phase A Observability JSON Export

_export_phase_a_observability_json saves a lightweight JSON report to reports/STRAT_observability_{timestamp}.json after every run unless export_observability_json=False. Contents: per-layer candidate counts, best wavelength, best P95 cost, Monte Carlo run count, and scan wavelength count.

7.3 Sensitivity Matrix (Legacy)

calculate_sensitivity_matrix sweeps $\sigma$ from 0 to 3 nm and computes the mean $|T_{noisy} - T_{nominal}|$ at each wavelength. This produces a two-dimensional heat map showing which spectral regions are most sensitive to thickness errors.
*Note: As of Revision 2026, explicit sensitivity exports have been streamlined; sensitivity is now evaluated intrinsically during Phase B screening.

7.4 SEEL Analysis (Legacy)

calculate_seel_analysis runs 3×50 Monte Carlo batches at 6 different $\sigma$ levels and computes the RMSE for each. The resulting SEEL curve indicates the equivalent random error per layer that the strategy can tolerate while staying within specification.
*Note: SEEL analytical bounds are now integrated directly into the Phase B dynamic Monte Carlo ranking rather than running as a standalone post-process.

7.5 Detailed Growth Visualization

calculate_detailed_growth simulates the exact transmittance curve during layer-by-layer deposition, including the dual-matrix backside correction. This produces the real-time $T(d)$ trace that the operator would see on the monitoring screen.

8. Implementation and Performance

8.1 Numerical Precision

Data Type Usage Precision
float64 Wavelengths, thicknesses, noise matrices ~15 significant digits
complex128 Refractive indices, TMM matrices (all phases) ~15 digits per component
A memory guard is applied during index precomputation: the estimated cache size (num_layers × num_wls × 2 × 4 × 8 bytes) is compared to adaptive limits (50–150 MB depending on stack size). If exceeded, the scan step is automatically coarsened to stay within the limit.

8.2 Parallelism

  • Numba @njit(parallel=True): All physics kernels use prange for automatic thread-level parallelism (wavelength and run loops).
  • ThreadPoolExecutor (mining): The 3 DP passes (THICKNESS / THICKNESS² / SYM) run concurrently within mine_strategies_for_block_count.
  • ThreadPoolExecutor (robustness): Robustness tasks run in parallel when get_safe_worker_count() > 1, sequential otherwise (frozen builds).
  • Throughput: ~10 million deposition scenarios evaluated per second (Core i9 reference).

9. Ergonomics and UI

The CERTUS suite uses a modernized UI for scientific workflows. The numerical kernels are JIT-compiled through Numba and use float64 and complex128 datatypes to preserve numerical stability.

9.1 Application Layout

CertusStratApp inherits from CertusBaseApp and uses a horizontal splitter layout with:

  • Left panel (scrollable): 4 tabs — Design, Optimization, Advanced, Why CERTUS.
  • Right panel: stacked plot area (WelcomeGuideWidget → main plot) + collapsible log panel (CertusLogPanel).
  • Status bar: toggle-details button, status label, live stats counter (♟ MS | 🎲 MCS | 🌈 SP), progress bar, theme toggle.

9.2 Global Keyboard Shortcuts

The interface maps the following shortcuts to the main workflow actions:

  • Ctrl + S: save the current configuration.
  • Ctrl + O: load an existing configuration.
  • F5 or Ctrl + R: launch the primary optimization step if enabled.
  • Ctrl + Z: undo the last configuration change.
  • Esc: close auxiliary floating windows.

9.3 Dynamic Processing Feedback

Long-running tasks are isolated in worker threads. The interface uses wait cursors and tooltips to keep the event loop responsive.

Numba JIT compilation runs in a background daemon thread at startup (_warmup_numba). Action buttons remain disabled until compilation completes, and _on_numba_ready_ui re-enables them on the Qt main thread via QMetaObject.invokeMethod.

9.4 Window Management

  • Plot Cache: PlotCache uses SHA256 hashing of data content (LRU, 20 items max) to prevent re-rendering identical Plotly figures.
  • Async Plot Renderer: PlotRenderWorker runs Plotly-to-PNG conversion in a dedicated QThread to keep the main event loop responsive.
