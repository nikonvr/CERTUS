### T1 — Donner l'espace excédentaire au graphe (`setStretchFactor`)

**Gain attendu : le plus important du document, pour le plus petit changement.**

#### Le problème

Aucun splitter principal de la suite ne déclare de facteur d'étirement. Quand la fenêtre
est plus large que la somme des tailles demandées, Qt distribue le surplus **à parts
égales** entre le panneau de contrôle et la zone graphique. Le panneau grossit donc sans
raison.

Vérifie-le toi-même :

```bash
grep -n "setStretchFactor" certus/ui/certus_base_app.py
```

**Sortie attendue avant correctif** : aucune ligne.

📏 **Mesure de validation faite le 2026-09-03 sur `CERTUS_INDEX`** : ajouter
`setStretchFactor(0, 0)` et `setStretchFactor(1, 1)` fait passer la zone graphique de
**58,0 % à 78,1 %**, sans toucher au contenu.

#### Ce qu'il faut faire

Fichier : **`certus/ui/certus_base_app.py`**, méthode **`_build_ui`**
(vers la ligne 1800, repère-la par son nom, pas par le numéro).

Cherche ce bloc :

```python
        main_splitter.addWidget(self.right_panel)

        # Initial sizes (Hook)

        main_splitter.setSizes(self._get_default_splitter_sizes())
```

Remplace-le par :

```python
        main_splitter.addWidget(self.right_panel)

        # Initial sizes (Hook)

        # The control panel keeps the width it asks for; every extra pixel goes to
        # the plots. Without these two lines Qt splits the surplus evenly, which
        # cost CERTUS-INDEX 20 points of plot area (58.0 % -> 78.1 %, measured
        # 2026-09-03).
        main_splitter.setStretchFactor(0, 0)
        main_splitter.setStretchFactor(1, 1)
        main_splitter.setSizes(self._get_default_splitter_sizes())
```

**Puis fais exactement la même chose dans les trois modules qui construisent leur propre
splitter principal**, en gardant le commentaire (une version courte suffit) :

| fichier | repère à chercher |
|---|---|
| `certus/ui/certus_index_ui_layout.py` | la ligne `self.main_splitter.setSizes([350, 700])` |
| `certus/metal/certus_metal_common.py` | la ligne `self.main_splitter.setSizes([440, 1080])` |
| `certus/ui/certus_strat_ui_layout.py` | méthode `apply_default_layout`, avant l'appel à `setSizes` |

Dans chaque cas, insère **juste avant** l'appel à `setSizes` :

```python
        self.main_splitter.setStretchFactor(0, 0)
        self.main_splitter.setStretchFactor(1, 1)
```

⚠️ Dans `certus_strat_ui_layout.py` la variable s'appelle `main_splitter` (locale), pas
`self.main_splitter`. Adapte le nom, **ne renomme rien**.


### T2 — Rendre les tables triables et redimensionnables

#### Le problème

📏 Mesuré : sur les **32 tables** des fenêtres principales, **zéro** n'est triable, et la
plupart n'ont aucune colonne ajustable. `setSortingEnabled(True)` n'apparaît qu'à un seul
endroit du dépôt, dans une fenêtre détachée.

C'est le geste le plus élémentaire d'un logiciel de métrologie : cliquer sur l'en-tête
d'une colonne de résultats pour trier.

#### Ce qu'il faut faire

La majorité des tables passent par une classe unique : **`ExcelTableWidget`**, dans
**`certus/ui/certus_ui_widgets_utils.py`** (vers la ligne 361).

Cette classe n'a **pas** de `__init__`. Ajoute-lui-en un, juste après la docstring de la
classe et **avant** `def keyPressEvent` :

```python
class ExcelTableWidget(QTableWidget):
    """Table with copy-paste"""

    def __init__(self, *args, **kwargs) -> None:
        super().__init__(*args, **kwargs)
        # Sorting and column resizing are expected of any metrology table.
        # Measured 2026-09-03: 0 of the suite's 32 main-window tables offered
        # either one.
        self.setSortingEnabled(True)
        header = self.horizontalHeader()
        if header is not None:
            header.setSectionResizeMode(QHeaderView.ResizeMode.Interactive)
            header.setStretchLastSection(True)

    def keyPressEvent(self, e) -> None:
```

Il faut importer `QHeaderView`. En haut du fichier, trouve la ligne qui importe depuis
`PyQt6.QtWidgets` et ajoute `QHeaderView` à la liste, en gardant l'ordre alphabétique.

#### 🔴 Piège à connaître

Quand le tri est actif, **remplir une table ligne par ligne réordonne les lignes au
fur et à mesure et corrompt l'affichage**. Le motif correct est de désactiver le tri
pendant le remplissage :

```python
table.setSortingEnabled(False)
# ... remplissage ...
table.setSortingEnabled(True)
```

Cherche donc tous les endroits qui remplissent une table et vérifie-les :

```bash
grep -rn "setRowCount(0)" --include=*.py certus/ | head -40
```

Pour **chaque** résultat, regarde la fonction qui l'entoure. Si elle ajoute ensuite des
lignes, encadre le remplissage par les deux appels ci-dessus.

#### Les tables qui n'héritent pas d'`ExcelTableWidget`

Ces quatre-là sont des `QTableWidget` bruts, il faut les traiter une par une :

| fichier | attribut |
|---|---|
| `certus/ui/certus_design_ui_layout.py` | `back_table`, `front_table`, `pareto_table`, `target_table` |
| `certus/ui/certus_field_common.py` | `table_layers` |
| `certus/ui/certus_field_state_mixin.py` | `pareto_table` |
| `certus/ui/certus_strat_multigraine_ui.py` | `_mg_table` |

⚠️ **N'active PAS le tri sur les tables d'édition** — `front_table`, `back_table` et
`table_layers` décrivent un **empilement optique où l'ordre des couches est la physique
même**. Trier ces tables donnerait un empilement faux. Pour celles-là, active uniquement
le redimensionnement :

```python
        header = self.ui.front_table.horizontalHeader()
        if header is not None:
            header.setSectionResizeMode(QHeaderView.ResizeMode.Interactive)
```

Active le tri **seulement** sur les tables de résultats : `pareto_table` (DESIGN et FIELD),
`target_table`, `_mg_table`.

```python
    def _refresh_synthesis_kpis(self, results) -> None:
        """Push the finished run's figures into the Synthesis banner."""
        banner = getattr(self, "kpi_banner", None)
        if banner is None or not results:
            return
        try:
            seel = results.get("seel")
            crash = results.get("crash_rate")
            banner.set_value("seel", f"{seel:.4f}" if seel is not None else PLACEHOLDER, "good")
            banner.set_value(
                "crash",
                f"{crash * 100:.2f} %" if crash is not None else PLACEHOLDER,
                "good" if (crash or 0) <= 0.05 else "bad",
            )
            banner.set_value("blocks", str(results.get("n_blocks", PLACEHOLDER)))
            banner.set_value("deposable", str(results.get("n_deposable", PLACEHOLDER)))
            banner.set_value("status", "Run complete", "good")
        except (ValueError, TypeError, RuntimeError, AttributeError):
            logging.getLogger("CERTUS").debug("KPI refresh skipped", exc_info=True)
```

### T6 — Raccourcir les libellés qui dictent la largeur des panneaux

#### Ce qu'il faut faire

### T7 — Compléter le clavier

#### Le problème

📏 Mesuré : `Ctrl+S` et `Ctrl+O` sont **absents d'INDEX, FIELD, METAL_SINGLE et
METAL_BILAYER** — quatre modules sur neuf ne savent ni sauvegarder ni charger au clavier.

n'a ni calcul ni configuration à sauvegarder. Ne lui câble rien.
Et **six modules ont un `undo_stack` sans aucun `Ctrl+Z`**.

#### Ce qu'il faut faire — partie A : sauvegarde et chargement

Un utilitaire existe : `install_standard_shortcuts` dans
`certus/ui/certus_ui_utils.py`. Il accepte `save=` et `load=`, et **ignore une séquence
déjà prise** (donc tu ne risques pas de créer de conflit).

Pour chaque module ci-dessous, trouve d'abord les vraies méthodes :

```bash
grep -rn "def save_config\|def load_config\|def save_configuration\|def load_configuration\|def _on_save\|def _on_load" --include=*.py certus/ui/ certus/metal/ | head -20
```

Puis complète l'appel existant à `install_standard_shortcuts` :

| module | fichier | appel à compléter |
|---|---|---|
| INDEX | `certus/ui/certus_index_ui_events.py` | méthode `_setup_shortcuts` |
| FIELD | `certus/ui/certus_field_ui.py` | l'appel après `self._finalize_init()` |
| METAL ×2 | `certus/metal/certus_metal_common.py` | vers la ligne 1167 |

Ajoute les deux arguments, en utilisant `getattr(..., None)` pour ne rien casser si la
méthode n'existe pas :

```python
            save=getattr(self, "<nom_reel_de_la_methode_save>", None),
            load=getattr(self, "<nom_reel_de_la_methode_load>", None),
```

🔴 **Si tu ne trouves pas de méthode de sauvegarde pour un module, ne câble rien pour
celui-là et signale-le.** Un raccourci qui pointe vers rien est pire qu'un raccourci
absent.

```python

```

⚠️ `undo_stack` existe sur la classe de base : sa simple présence **ne prouve pas** que
le module implémente réellement l'annulation. Vérifie qu'une méthode d'annulation existe
